# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

GPS navigator with a Cyberpunk aesthetic, as a PWA. Vite + vanilla
TypeScript + MapLibre GL JS. No UI framework.

The **README** covers what the app does and its folder structure.
**`docs/status.md`** covers status by phase and what's left.
**`docs/findings.md`** covers the eleven pitfalls that cost time: **read it
before "cleaning up" anything in the code that looks odd.** Almost
everything odd is that way for a measured reason.

## Commands

The repo is an **npm workspace**: everything runs from the root, not from
`app/`.

```bash
npm install            # installs the workspace
npm run dev            # dev server with hot-reloading of the style
npm test               # the 47 tests
npm run build          # tsc --noEmit && vite build
npm run deploy         # build + wrangler deploy
```

**A single test** — this one does need `--prefix`, because the argument
doesn't survive the workspace delegation (`npm test -- session` from the
root finds nothing):

```bash
npm --prefix app test -- session     # session.test.ts only
npm --prefix app run test:watch      # watch mode
```

**Regenerating artifacts** after touching their generators:

```bash
npm run style    # style/cyberpunk.json
npm run sprite   # POI sprite + style
npm run icons    # PWA icons
```

Validate the deployment without credentials: `npm run build && npx wrangler deploy --dry-run`

## Generated artifacts: do not hand-edit

- **`style/cyberpunk.json`** is generated by `style/build.mjs` from a
  palette and a road-class table. Editing the JSON gets lost on the next
  regeneration, and the dev server triggers it on its own when `build.mjs`
  is saved.
- **`app/public/sprites/*`** and **`app/public/icons/*`** are generated by
  the scripts in `assets/`.
- **`assets/lib/poi-icons.mjs`** is the **single source of truth** for POI
  icons: the glyphs and which business type gets each one. Both the sprite
  generator and the style generator pull from it, so they can't get out of
  sync. A class in two lists throws an error at generation time, on
  purpose: a MapLibre `match` expression rejects repeated tags, and that
  would break the whole style on load.

## Architecture rules that cross multiple files

These can't be figured out by reading a single file in isolation, and
breaking them produces silent failures:

**`services/geolocation.ts` is the sole owner of `watchPosition`.** Nothing
else calls the geolocation API. It used to be owned by the diagnostics
panel and had to be extracted; don't put it back there or open a second
watcher.

**`nav/` is pure logic except for `session.ts`.** `snap`, `progress`, and
`off-route` don't touch the network, the DOM, or the clock beyond receiving
values. `session.ts` is the only impure orchestrator, and **it must not
make HTTP requests**: it decides *when* a new route is needed and notifies
via `onNeedsReroute`; whoever calls the API is `main.ts`. That's what makes
it possible to test the whole state machine with synthetic readings, and
it's the only way to verify this without driving.

**Heading has its own rule in `services/heading.ts`:** the GPS leads while
moving (and for 6 s after), the compass leads the rest of the time. With
the phone in a mount, where the device points isn't where the car is going.

**`map/map.ts` has three distinct cameras**, and mixing them up was the
source of a real bug: normal following, `fitRoute()` for the preview, and
`startNavigation()` with a fixed zoom, tilted, and with the marker offset.
The navigation one **never zooms out**, by design.

**`RouteLayer` repaints itself** on hearing `style.load`, because
`setStyle` wipes out hand-added sources and layers. Don't add coordination
for that in `main.ts`.

**`main.ts` resolves the sprite URL against `location.origin`** before
handing the style to the map. MapLibre requires it to be absolute — unlike
tile and glyph URLs — and the style keeps a relative one to stay portable
between localhost and production.

**In `#ui`, `pointer-events` are opt-in** (`.panel`, `.btn`). With the
previous rule (`#ui > *`), an invisible layout container was swallowing
every gesture meant for the map. Don't turn it back on for all children.

**`[hidden] { display: none !important }`** is in `style.css` on purpose:
the browser applies `hidden` from its own stylesheet, which loses against
any `display: flex` rule of ours.

## Verification: what this environment can't check

In the automated browser the document is **hidden**, so
`requestAnimationFrame` never fires. Practical consequences:

- **MapLibre never finishes loading the style** (`isStyleLoaded()` stays
  `false`, zero features, and **no error is ever emitted**). Don't mistake
  this for a bug in the code.
- **`easeTo` doesn't animate**, so camera behavior can't be verified.
  `jumpTo` is immediate, though: use it to prove the map object responds,
  rather than chasing a ghost.
- Pumping frames by hand ends up **freezing the renderer**. See
  `docs/findings.md` §5 before trying it.

So: **look at the screenshots, don't trust reading properties.** The search
overlay showed up open on every load while `el.hidden` returned `true`; it
was only caught by looking at the screen. And when drawing icons or arrows,
lay them all out in a gallery and look at them: that's how three crooked
maneuver arrows were caught.

The navigation tests use **synthetic GPS traces generated by walking a real
polyline** (`app/src/services/routing.fixture.ts`), including a ±60 m noise
case that must **not** declare a deviation.

## Constants chosen by eye

They have the right shape but the value hasn't been tuned on the road. If
something feels off while using it, it's probably here (full table with
symptoms in `docs/status.md`):

| Constant | File |
|---|---|
| 32 px drag intent | `map/map.ts` |
| `max(35, accuracy × 2.5)` deviation | `nav/off-route.ts` |
| 15 s between reroutes | `nav/session.ts` |
| 1.5 m/s to trust the GPS heading | `services/heading.ts` |

## Services and keys

**There is no API key in the code, and there shouldn't be one.** Stadia
Maps authenticates by domain, validating `Origin` and `Referer`. On
`localhost` it works with nothing configured. If `401 No valid
authentication provided` shows up in production, it means the domain needs
to be registered in Stadia's panel, not that a key is missing.

Tiles are from OpenFreeMap and need no authentication.
